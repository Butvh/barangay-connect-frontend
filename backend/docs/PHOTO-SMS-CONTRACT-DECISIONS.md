## Explicit SMS-intent dependency

P2's Module::event still emits only in-app recipients, and TypedOutboxWriter rejects sms=true. Its actual in-app production-adapter probe passes; a separate fake SMS-intent probe truthfully reports p2_sms_intent_contract_not_implemented with zero provider attempts. No approved persisted production fixture is available, so DBA does not invent one or silently upgrade in-app recipients.

| Persisted event | Only eligible SMS route/template | Required P1/P2 contract before producer acceptance |
| --- | --- | --- |
| incident.created.v2 | urgent Laravel worker directly to Semaphore; alert-review.v1 | Authorized source transition, explicit allowed audience/recipient IDs and permission/consent; same source transaction and relational recipient sms flag; snapshot/replay/revocation rules. |
| announcement.published.v2 | approved nonurgent Make webhook -> scoped Laravel command -> existing SMS ledger; announcement-review.v1 | Approved audience and consent/permission, explicit persisted intent, immutable event/template/scope, callback/replay/revocation rules. |
| All other v2 families | SMS denied | No registry, config flag, phone presence, in-app permission or Make callback can grant SMS. |

P2 must publish actual business-producer and typed-writer fixtures for allowed/denied channels, caller rollback, duplicate intent, tenant/audience rejection and source/recipient revocation. P1 reviews recipient/channel authority and retains disabled production defaults. DBA then runs the existing separate sms-intent production-adapter probe and fake delivery/reconciliation suite against those exact fixtures; no second writer/dispatcher/ledger is added. Numbers, message bodies, URLs and provider credentials never enter caller-selected event payloads. Runtime allowlist, segment budget/rate, provider uncertainty and callback credentials remain independent DBA gates.

All normal tests use fakes. No live provider send, paid action, Make activation or production worker evidence is requested or implied. This decision record and concrete owner requests are linked from PR49/50; implementation follows explicit ratification, not silence or elapsed time.
